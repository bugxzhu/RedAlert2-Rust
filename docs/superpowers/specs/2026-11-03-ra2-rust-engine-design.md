# 红色警戒2 Rust 引擎重实现 — 设计文档

日期:2026-11-03
状态:已与发起人逐节确认
许可证:GPL-3.0(见 §9)

## 1. 项目定位与边界

### 1.1 目标

用 Rust 重写《红色警戒2:尤里的复仇》游戏引擎(开源、跨平台),目标是**感知级保真的重实现**:

- 加载玩家自备的原版游戏资产(MIX/INI/地图),不分发任何 EA 版权资产
- 遭遇战(Skirmish)完整可玩:建造、生产、战斗、迷雾、简单 AI、胜负判定
- 观感与行为"像原版":玩家对战中无法察觉显著差异
- 架构上为联机(锁步)、战役(触发器)、Ares 兼容预留接口,但本设计不含其实现

### 1.2 非目标(本设计明确不做)

- 联机对战与回放系统(另立 spec)
- 战役/触发器系统(另立 spec)
- Ares/Phobos 扩展 INI 标签的兼容(另立 spec)
- 位级二进制兼容(不追求与 gamemd.exe 状态逐位一致、不追求直接运行 Ares DLL)
- 主菜单/大厅 UI(通过 CnCNet spawner 协议复用现成客户端,见 §7.1)

### 1.3 保真度定义

**感知级保真**:规则数值(伤害/成本/射程/速度)、UI 交互、音效语音、视觉表现与原版一致或差异不可感知。验证手段为 oracle A/B 对拍(§8.4),而非反汇编逐指令等价。

## 2. 规格来源(如何"准确复制"一个源码丢失的游戏)

引擎规格从以下五层信息源提取,按可信度排序。**下层覆盖上层**:冲突时以更接近二进制真相的来源为准。

| 层 | 来源 | 提供什么 | 授权状态 |
|---|---|---|---|
| 0 | RA1 源码 `F:\redalert\CnC_Red_Alert`(约 30 万行 C/C++) | 血统继承的算法与模型:RNG(`RAND.CPP`)、MIX 容器、INI 框架、锁步事件模型、触发器/小队概念、A* 寻路 | GPL-3.0,可直接移植 |
| 1 | YRpp(Ares-Developers,C++ 头文件库) | gamemd.exe 1.001 的类布局、成员偏移、虚表——"丢失的头文件"的社区重建 | 开源 |
| 2 | Ares / Phobos / CnCNet spawner / Syringe 源码 | 引擎行为的规格文档(hook 注释、spawn.ini 协议、扩展语义) | 开源(GPL 系) |
| 3 | ModEnc / PPM 社区 wiki | 数百个 rulesmd.ini 标签的实测语义 | 公开文档 |
| 4 | gamemd.exe 1.001(用户自有副本,MSVC6 编译,RTTI 开启) | 最终裁决(oracle):可反编译读算法、可运行做行为对照 | 仅作逆向与观察对象,**不复制其代码** |

实证:gamemd.exe 内可一条命令提取 328 个 RTTI 类名(`.?AV...@@`),引擎类体系(`AbstractClass→TechnoClass→FootClass→UnitClass`、`SidebarClass`、`HouseClass`、`AITriggerTypeClass` 等)完全可恢复。深度反编译需配置 Ghidra(`GHIDRA_INSTALL_DIR` 指向 Ghidra 12.1.x)后经 REA 工具链进行。

### 2.1 法律红线

- **绝不使用**任何网上流传的 TS/RA2 时代"泄漏源码"(非 GPL 授权,接触即污染开源项目)
- 只使用:(a) GPL 的 RA1 源码(可移植,前提是本项目 GPL-3.0);(b) 对自有二进制的逆向分析(规格提取,clean-room 纪律:从反编译学语义,用 Rust 重写,不逐行翻译机器码);(c) 黑盒行为观察
- 分发不含任何 EA 资产;启动时要求用户指定自备的原版游戏目录(如 `E:\hongjing\Reunion 2023`,含 `ra2.mix`/`ra2md.mix` 等原版 MIX)

## 3. 总体架构(cargo workspace)

```
ra2-rs/
├── crates/
│   ├── core/               纯逻辑层。零 IO、零图形依赖(仅 std + 格式解析)
│   │   ├── format/         mix, pal, shp, tmp, csf, vxl, hva, aud, ini
│   │   ├── rules/          rulesmd.ini / artmd.ini 子集 → 强类型规则库
│   │   ├── sim/            固定步长世界模拟:对象/任务状态机/寻路/战斗/生产/迷雾
│   │   └── replay/         命令流(黄金测试与未来联机共用抽象)
│   ├── view/               wgpu 渲染:等距地形/SHP 精灵/VXL 体素/小地图纹理
│   ├── ui/                 位图资产 UI 工具包(侧边栏/按钮/帧动画/位图字体)
│   └── shell/              winit 窗口 + 输入 + 音频(kira)+ 组装;
│                          含 CnCNet spawner 协议入口(-SPAWN / spawn.ini)
├── tools/
│   └── viewer/             资产/地图查看器(格式层的可视化测试台)
└── docs/
```

依赖方向严格单向:`shell → ui/view → core`。`core` 不依赖任何渲染/窗口/音频库,可在 CI 无 GPU 环境全量测试。

### 3.1 确定性铁律(sim 层)

1. 禁浮点:数值用定点数(i32/i64 分数表示,参考原版定点用法)
2. 禁不确定迭代:不遍历 HashMap/HashSet(除非按显式排序后遍历);对象集合用 Vec + 稳定索引(句柄式引用,避免指针比较)
3. 随机数:显式种子注入的 Westwood RandomClass 移植版;任何 sim 决策只经此 RNG
4. 禁系统时间/环境依赖:sim 内所有"帧号驱动"
5. 渲染层只读世界快照,不回写

## 4. 关键技术方案

| 领域 | 方案 | 规格/参考来源 |
|---|---|---|
| MIX 解包 | RA2 校验和算法(与 RA1 的差异已由 XCC 文档化)+ Blowfish 索引解密(Botham/LowEnd 变体) | RA1 `MIXFILE.CPP` + XCC 文档 + YRpp |
| SHP 精灵 | 三种压缩格式(未压缩/LCW/无损 RLE)解码 → 调色板索引帧 | RA1 `LCW.CPP` 可移植 |
| 等距地形 | TMP 瓦片按菱形栅格渲染,含高度图/斜坡/悬崖;地图二进制段(IsoMapPack5)LZO 解压 | TS 社区文档 |
| VXL 体素 | CPU 实时光栅化(逐面元投影 + 法线光照 + HVA 帧姿态),参照 OpenRA RenderVoxel | OpenVA/VXL 格式文档 |
| 寻路 | A*,RA1 `FINDPATH.CPP`(1294 行)思想移植 + RA2 网格规则(悬崖/水位/隧道) | RA1 源码 + oracle 调参 |
| 规则系统 | 手写容错 INI 解析(未知标签告警不失败)→ 强类型规则库;语义以 ModEnc + oracle 实测为准 | ModEnc + Ares 源码 |
| RNG | Westwood RandomClass 移植(RA1 `RAND.CPP`,算种延续至 TS/RA2) | RA1 源码 |
| 帧模型 | 固定逻辑步长 + 渲染插值;确切 tick 率在 M2 期以 oracle 实测确定(候选 60/s 与帧跳过模型) | oracle 实测 |
| 音频 | AUD(IMA ADPCM)解码 → kira 混音;EVA 事件驱动的语音/音效播放 | 格式文档 |

## 5. 里程碑(AI 主导开发,按可独立验证单元切片)

每个里程碑有明确验收标准,完成后立即对拍验证。

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| **M0** 脚手架 | workspace + GPL-3.0 文件 + CI(test/clippy/fmt)+ 无头冒烟测试 | CI 绿 |
| **M1** 格式层 | MIX/PAL/SHP/TMP/CSF/VXL/HVA/AUD/INI 解析器 + 资产查看器 | 对用户原版 MIX 全量解析零 panic;查看器显示 SHP/VXL/瓦片/字符串 |
| **M2** 地图渲染 | .map 解析(INI+二进制段)、等距地形、物件、视口滚动 | 加载官方标准图,截图与原版结构一致(§8.3 快照测试) |
| **M3** 建造闭环 | rulesmd 子集、侧边栏 HUD、建造队列/金钱/电力/放置 | 通过 UI 建造完整基地,资源与电力规则与原版一致 |
| **M4** 单位战斗 | 对象状态机(任务/行动)、A* 寻路、武器/弹道/伤害、迷雾、选择/编队/命令 | 单位行为可操作;伤害公式 oracle 对拍通过 |
| **M5** 遭遇战闭环 | 采集经济、简单 AI(采集→生产→进攻波)、胜负、EVA | 完整打赢/打输一局遭遇战;黄金回放回归测试建立 |
| **M6+** | 联机(锁步)/战役(触发器)/Ares 容错 | 另立 spec |

## 6. 测试策略

1. **黄金回放**:固定地图 + 固定命令序列 → 每 N 帧计算世界状态哈希;回归测试基线入库(不含资产,只有哈希)。这是无 GPU 环境下的核心回归手段
2. **快照测试**:渲染帧与基准 PNG 比对(带容差);基准图生成时人工确认
3. **格式 round-trip**:对用户资产解码→重编码/哈希校验;LCW 等算法与 RA1 源码实现对拍(同输入同输出)
4. **oracle A/B 对拍**:争议行为(伤害公式、命中判定、AI 触发)在原版 gamemd.exe 实测取证(可用 Syringe/Ares 调试输出),记录为规格测试用例
5. CI 策略:CI 只跑合成资产与哈希基线(不含 EA 资产);真实资产测试在本地 `cargo test -- --ignored` 跑,资产目录经环境变量 `RA2_ASSETS_DIR` 指定

## 7. UI 复现策略

### 7.1 三层结构

- **游戏外(主菜单/大厅)**:不复现。实现 CnCNet spawner 协议(命令行 `-SPAWN` + 读 `spawn.ini`),可直接被重聚2023/CnCNet 客户端调起,复用其现代化大厅。同时提供独立的"直接启动遭遇战"最小入口用于开发
- **游戏内 HUD(核心)**:视觉 100% 使用原版 MIX 资产(侧边栏背景/按钮/页签 = `shellmd.mix` 的 SHP;建造图标 = `ecache*.mix` 的 cameo;光标 = 动画 SHP;文字 = 原版位图字体)。布局坐标优先从 YRpp/Ares 提取,初期近似对齐,后续截图逐像素校准
- **细节行为**:建造完成闪烁、断电雷达雪花、小地图点击/框选、侧边栏滑入等,属交互状态机,随 M3-M5 逐步实现

### 7.2 位图 UI 工具包

`crates/ui` 实现专为调色板位图资产设计的保留模式 UI 原语:SHP 按钮/帧动画/九宫格缩放/调色板闪烁(资金不足 cameo 变红)/位图字体渲染。不采用矢量 UI 框架(egui 等)。

### 7.3 分辨率适配

原版 640×480/800×600 → 现代任意分辨率:侧边栏保持原始宽度不拉伸,战场视口向左/上扩展(照抄 Ares 成熟做法);位图整数倍缩放保持像素观感。

## 8. 法律与分发

- 引擎代码 GPL-3.0(与移植 RA1 代码的要求一致,亦与 OpenRA 同惯例)
- 不分发、不内嵌任何 EA 版权资产( MIX/音乐/语音/地图)
- 用户自备资产:首次启动指定原版游戏目录,持久化到本地配置
- 本仓库不提交任何原版资产文件;测试基线只含哈希与合成样本

## 9. 风险与应对

| 风险 | 概率 | 应对 |
|---|---|---|
| VXL 体素渲染性能/观感不达标 | 中 | 备选:离线预渲染多朝向精灵;或 GPU 实例化体素 |
| rulesmd 语义陷阱(数百标签) | 高 | 分层实现:核心标签先保真,未知标签告警;oracle 对拍补充 |
| 确定性被无意破坏(编译器/平台差异) | 中 | 定点数 + 禁浮点 lint(sim 层 deny);黄金回放跨平台 CI 校验 |
| Ghidra/REA 环境配置阻碍 RE 进度 | 低 | 环境问题一次性解决;规格提取不阻塞 M0-M1(格式层已有文档) |
| 范围蔓延(联机/战役/兼容性需求提前涌入) | 高 | 本设计的"非目标"清单为硬边界,新特性一律另立 spec |
